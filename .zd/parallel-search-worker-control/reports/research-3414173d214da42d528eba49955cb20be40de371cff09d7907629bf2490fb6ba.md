# Research report: parallel-search-worker-control

## Question

> Verify issue parallel-search-worker-control-011: Validate the Origin and Variant API migration

## Summary

> The captured sources show that the Origin/Variant implementation, focused dispatch tests, and migration documentation cover the central API and behavioral contracts, but issue 011 is not fully validated. The implementation exposes `Space::origin` and `Space::variant`, preserves the documented default behavior, keeps RBS return values meaningful, and ignores PBS return values while invoking Variant for single, sequential, and parallel portfolios with zero-based asset indices. The focused tests override Origin alone, Variant alone, and both hooks, and exercise RBS restart/completeness decisions plus the main PBS configurations. The migration notes give the exact old-to-new override mapping and state that there are no compatibility aliases. Missing from the packet are an explicit negative compile test proving the old hook names cannot override, a buildable migration example, focused evidence for custom no-good and incumbent handling, explicit lifecycle validation for cloning ownership and stop/reset, complete-suite and documentation/example build results, and an exhaustive classified terminology sweep. On this evidence, the migration is substantially implemented and behaviorally covered, but the issue's complete acceptance and validation criteria remain unproven.

## Findings

### The public implementation uses Origin and Variant and preserves default behavior

> `Space::origin` implements the existing RBS default of constraining against the last solution and posting no-goods, and the PBS default of killing common branchers. `Space::variant` remains a no-op returning `true`.

Evidence:
- `gecode/kernel/core.cpp` — > bool
>   Space::origin(const MetaInfo& mi) {
>     switch (mi.type()) {
>     case MetaInfo::RESTART:
>       if (mi.last() != nullptr)
>         constrain(*mi.last());
>       mi.nogoods().post(*this);
>       // Perform a restart even if a solution has been found
>       return true;
>     case MetaInfo::PORTFOLIO:
>       // Kill all branchers
>       BrancherGroup::all.kill(*this);
>       return true;
>     default: GECODE_NEVER;
>       return true;
>     }
>   }
> 
>   bool
>   Space::variant(const MetaInfo&) {
>     return true;
>   }
- `docs/gecode-7-migration.md` — > - The default RBS Origin behavior still constrains against the last solution,
>   posts no-goods, and requests a restart.
> - The default PBS Origin behavior still removes common branchers before
>   asset-specific branching is installed.
> - The default Variant behavior still performs no additional configuration and
>   returns `true`.

### RBS still interprets both callback results

> After a solution, the Origin result decides whether to rebuild the exploration. The Variant result is stored as the exploration-completeness flag, and that flag controls whether exhaustion causes another true restart. The implementation retains a clone as the next Origin and resets the underlying engine with the prepared Variant.

### Migration documentation gives the exact override mapping but not a buildable example

> The migration notes clearly map both Gecode 6 hook declarations to their Gecode 7 replacements, require `override`, and state that compatibility aliases do not exist. In the captured source, this is a documentation snippet rather than a standalone executable migration example.

Evidence:
- `docs/gecode-7-migration.md` — > ```cpp
> // Gecode 6
> bool master(const Gecode::MetaInfo& mi) override;
> bool slave(const Gecode::MetaInfo& mi) override;
> 
> // Gecode 7
> bool origin(const Gecode::MetaInfo& mi) override;
> bool variant(const Gecode::MetaInfo& mi) override;
> ```
> 
> There are no compatibility aliases. Keeping `override` on model hooks makes
> the compiler identify every model that still uses a Gecode 6 signature.
- `.zd/parallel-search-worker-control/issues/011-validate-the-origin-and-variant-api-migration.md` — > - [ ] The migration example builds against the Gecode 7 headers and gives users an exact old-to-new override mapping.

## Limitations

- The packet contains source snapshots, not build or test command output. It cannot prove that the complete search suite passed in sequential and threaded configurations or that documentation and examples built.
- No captured header declaration is provided, so the packet cannot directly verify the public declaration surface or prove that old `master` and `slave` members are absent. The new overrides compile only if `test/search.cpp` itself was successfully built, and no build result is included.
- The captured sources do not include a standalone migration example or evidence that the documentation snippet was compiled against Gecode 7 headers.
- Focused tests exercise callback dispatch and RBS return semantics, but the packet does not show migration-focused assertions for custom no-good posting, custom incumbent handling, or explicit cloning-ownership and stop/reset lifecycle outcomes.
- The terminology examples in the packet are classifiable, but no exhaustive scan inventory or attached sweep report proves that every remaining case-sensitive and case-insensitive occurrence in maintained source, tests, examples, and documentation was reviewed.
- No `zd issues check parallel-search-worker-control` result is included.

## Recommendations

- Add an explicit compile-pass fixture that overrides both new signatures and compile-fail fixtures for the old signatures, so API presence and removal are independently enforced.
- Add a small buildable migration model under the examples or documentation test harness that uses both new overrides and is compiled with the Gecode 7 headers.
- Extend focused tests to assert default and custom no-good behavior, incumbent propagation, clone-shared versus clone-owned observation state, and stop/reset behavior for RBS and PBS.
- Run and record the complete sequential and threaded search suites plus the documentation/example build; include the exact configurations and results as issue evidence.
- Attach a complete case-sensitive and case-insensitive terminology inventory, classify every occurrence as unrelated, historical migration text, third-party material, or defect, and fix any stale meta-search terminology.
- After linking the missing evidence, run `zd issues check parallel-search-worker-control` and record the result before closing issue 011.
