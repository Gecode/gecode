# Research report: parallel-search-worker-control

## Question

> Research issue parallel-search-worker-control-001: Specify the parked-worker scheduler state machine

## Summary

> Recommendation: add a scheduler to the shared parallel engine whose worker state is the product of logical search state and execution permission. Logical state is OWNER when `cur != nullptr` or `path` retains a next branch, PENDING while a non-idle worker has not yet completed its empty-state transition, and IDLE after it has reported exhaustion. Permission is SLOT or NO_SLOT. The useful combined states are ACTIVE_OWNER, PARKED_OWNER, ACTIVE_THIEF, and PARKED_IDLE; lifecycle commands temporarily supersede all four.
> 
> Preserve `n_busy` as the exhaustion counter, not the slot counter. It counts workers not yet declared IDLE, including a PARKED_OWNER and the existing short-lived PENDING state. Parking never changes `idle`, `cur`, `path`, statistics, tracer state, or BAB state, and never calls `Engine::idle()`. A successful steal by an IDLE worker still calls `busy()` once; a worker calls `idle()` once only after `cur == nullptr` and `path.empty()`. Consequently `n_busy == 0` keeps its present meaning: every worker has accounted for all local work, independent of how many have execution permission.
> 
> Scheduler data belong to the fixed-capacity engine: atomic `requested` in `1..workers()`, scheduler mutex, `n_slots`, one `has_slot` flag and one sticky park event per worker, logical-state mirrors updated only at safe boundaries, and an owner-prioritized round-robin wait queue. Initialize at most `requested` leases, including worker zero when it owns the root. A lease authorizes search only while the command is C_WORK; it does not transfer or own a path.
> 
> At the top of every worker-loop iteration, before acquiring the worker mutex, load the command. Commands other than C_WORK bypass slot admission. For C_WORK, a worker that already has a slot and sees `requested == maximum` takes the unchanged-limit fast path. Otherwise it reconciles under the scheduler mutex. A slot holder relinquishes its lease when `n_slots > requested`; a waiter acquires one only when `n_slots < requested`. A worker without a lease records itself parked, releases the scheduler mutex, and waits on its own event in a predicate loop that rechecks both command and lease. Never park while holding the worker mutex or any engine/barrier mutex.
> 
> One admitted worker action is exactly one existing safe loop action: stop check plus `status()`, one branch commit, one recomputation, one solution handoff, an empty transition, or a complete steal scan. Resizing therefore does not interrupt propagation or recomputation. Shrink converges as currently executing workers reach boundaries; after convergence, no new action begins with more than `requested` leases. Growth signals parked events, whose contenders serialize under the scheduler mutex and cannot exceed the limit.
> 
> Execution-slot migration is a direct permission handoff, not path migration. An ACTIVE_THIEF may scan every fixed worker with the existing `steal()` operation. If it steals, it becomes ACTIVE_OWNER and retains its lease. If the scan fails while `n_busy > 0`, it relinquishes its lease under the scheduler mutex and grants or queues it to the next parked non-IDLE worker, preferring OWNER over PENDING and using round-robin order. Signal the selected worker after unlocking. False-positive PENDING candidates execute one boundary, become IDLE if empty, and repeat the handoff. When an owner exhausts its local branch and `n_busy` remains positive, it performs the same handoff after `idle()`.
> 
> Progress argument: assume each existing search action terminates, runnable OS threads are eventually scheduled, the command remains C_WORK, and `requested >= 1`. Maintain the invariant that `n_busy > 0` implies at least one lease or one recorded handoff to a waiter. If the lease holder owns work, it advances that work. If it is empty, it either steals an alternative or hands the lease through a finite round-robin set. Stale PENDING entries disappear after one action. Thus, when a parked owner holds the remaining current branch, the lease reaches it even when that branch is not stealable. `next()` cannot report exhaustion because parking does not decrement `n_busy`, and it cannot wait forever merely because all former slot holders became idle.
> 
> Command protocol: C_WORK releases the existing global wait lock and signals enough parked candidates to reconcile growth or a changed lease set. C_WAIT stores the command before acquiring the global wait mutex. Current slot holders finish one bounded action and enter the existing wait lock; scheduler-parked workers are already quiescent and may remain on their park events. A limit update during C_WAIT may signal them, but their predicate sends them to command handling rather than search. C_RESET and C_TERMINATE store the command, signal every per-worker park event, and then release the global wait lock. All construction-time workers therefore acknowledge the existing fixed-membership barriers regardless of slot state. Event stickiness covers the race in which the command signal precedes `wait()`.
> 
> During C_RESET, after all start acknowledgements and while workers are blocked on `m_wait_reset`, reset logical states and `n_busy` as today, clear all leases, then grant a deterministic set of `min(requested, workers())` leases including worker zero. Recheck `requested` on the next C_WORK boundary to cover a concurrent late update. No-good extraction uses the same C_RESET rendezvous but preserves search/path ownership and can preserve the lease set after all workers acknowledge. C_TERMINATE ignores leases after wakeup: every worker acknowledges exactly once, waits for legal termination, and returns.
> 
> Lock discipline: worker code enters the scheduler only with its worker mutex released. The scheduler mutex is never nested with a worker mutex, `m_search`, `_m_reset`, `_m_term`, `_m_wait`, `m_wait_reset`, or `_m_wait_terminate`; event waits and signals occur after releasing it. Preserve the existing BAB order `m_search` then worker mutex for `solution()`, `constrain()`, and `better()`, but never add scheduler acquisition inside that region. Publish `_cmd` before lifecycle wakeups. Update `n_busy` under `m_search`, release it, and only then perform a scheduler handoff. This removes a worker/scheduler cycle and retains current BAB synchronization.
> 
> Use one existing `Support::Event` per worker. A shared Event is invalid because its contract permits one waiter. Per-worker events match that contract, retain signals issued before waiting, allow targeted owner wakeups, compile through Gecode's threaded and non-threaded support abstraction, and require no new support API. A new multi-waiter primitive would centralize broadcast but enlarges support-layer scope. A direct `std::condition_variable` would require separate conditional compilation and a compatible mutex/predicate protocol; changing an atomic limit without holding that predicate mutex risks a lost notification. Per-worker events cost no wait operation on the unchanged maximum path; growth and lifecycle transitions may perform O(maximum) signals, which is acceptable for infrequent control changes. Because Gecode mutexes promise no fairness, progress comes from the explicit round-robin queue, not the waiting primitive.
> 
> DFS needs no path changes: parking retains the current `cur/path` invariant, and stealing remains the only branch transfer. BAB additionally relies on the existing per-worker mutex path for incumbent delivery. A parked worker can receive `best` and `mark` updates while asleep; after admission it recomputes or explores under the incumbent already installed. Solution order, node count, and which worker explores a branch may change, but branch ownership, completeness, and incumbent pruning invariants remain intact.

## Findings

### Logical work and execution permission must be independent

> The settled boundary requires parked workers to retain search state. Model ownership separately from a migratable slot, and keep `n_busy` tied to logical non-idleness. The current implementation initializes `n_busy` from fixed worker capacity and changes it only through `idle()` and successful stealing through `busy()`; parking must not use either transition.

Evidence:
- `.zd/parallel-search-worker-control/brief.md` — > - Parked workers retain their current space, path, statistics, and BAB incumbent state. They may keep an operating-system thread blocked, but they do not consume a search execution slot.
- `.zd/parallel-search-worker-control/brief.md` — > - Separate logical ownership of unexplored search from permission to execute. A parked worker can remain logically busy.
- `gecode/search/par/engine.hpp` — > // Initialize search information
>     n_busy = workers();
>     has_stopped.store(false, std::memory_order_release);

### The worker-loop boundary is the safe resize boundary

> Both DFS and BAB dispatch one bounded search action from C_WORK while holding the worker mutex and return to the command switch afterward. Slot reconciliation belongs before that mutex acquisition. It must never interrupt `status()`, commit, recomputation, or solution processing.

### Failed stealing must migrate the slot to an owner

> Stealing transfers only alternatives that `Path::steal()` considers available. A parked worker may instead own only its current branch, which cannot be stolen. After a complete failed scan, an active idle worker must hand its execution lease to a queued non-idle parked worker. Owner priority plus round-robin traversal establishes progress without migrating paths.

Evidence:
- `.zd/parallel-search-worker-control/brief.md` — > - Require execution-slot migration: when active workers exhaust local work while parked workers still own work, a parked owner must be allowed to run.

### Parking must not alter exhaustion or solution signaling

> `next()` currently treats only `n_busy == 0` as exhaustion and waits on `e_search` otherwise. Because a parked owner remains busy, no false exhaustion signal is emitted. Slot handoff is required when the last executing thief becomes idle, otherwise `next()` would correctly refuse exhaustion but have no worker able to produce the next event.

Evidence:

### Lifecycle commands supersede slot admission

> The fixed worker set remains the reset and termination barrier membership. C_RESET and C_TERMINATE must wake every scheduler-parked worker before waiting for acknowledgements. C_WAIT may leave scheduler-parked workers asleep because they are already quiescent, while C_WORK wakes candidates needed to satisfy the requested limit.

Evidence:
- `gecode/search/par/engine.hh` — > enum Cmd {

### Reset and termination barriers require explicit scheduler reconciliation

> Reset waits for every worker, rewrites every worker state, restores `n_busy`, and then blocks them again. This is the safe point to rebuild lease state from the current requested limit. Termination likewise releases all workers and waits for both acknowledgement and actual thread termination; parked workers cannot remain outside this sequence.

### BAB incumbents can update parked owners without granting a slot

> BAB delivers incumbents under `m_search` and each worker mutex. A parked worker does not hold its mutex, so `best`, `mark`, and `cur` can be updated while it lacks execution permission. Scheduler code must not introduce a reverse worker-mutex-to-scheduler or scheduler-to-`m_search` nesting order.

Evidence:
- `gecode/search/par/bab.hpp` — > BAB<Tracer>::Worker::better(Space* b) {
>     m.acquire();
>     delete best;
>     best = b->clone();
>     mark = path.entries();
>     if (cur != nullptr)
>       cur->constrain(*best);
>     m.release();
>   }
- `gecode/search/par/bab.hpp` — > // Announce better solutions
>     for (unsigned int i=0U; i<workers(); i++)
>       worker(i)->better(best);
- `gecode/search/par/bab.hpp` — > if (best != nullptr)
>           cur->constrain(*best);
- `.zd/parallel-search-worker-control/brief.md` — > - BAB returns a proven optimum across the same sequences and remains correct when incumbents arrive while workers are parked.

### Choose one sticky Support::Event per worker

> The existing Event is explicitly single-waiter, stores a pending signal, and waits with a predicate. One event per fixed worker therefore avoids lost wakeups and supports targeted handoff. A shared Event is unsuitable. Direct standard-library condition variables would bypass the existing support abstraction, while a new multi-waiter support primitive adds scope. Explicit round-robin scheduling is necessary because the existing mutex has no fairness guarantee.

Evidence:
- `gecode/support/thread.hpp` — > An event can be waited on by a single thread until the event is
>    * signalled.
- `gecode/support/thread/thread.hpp` — > Event::signal(void) {
> #ifdef GECODE_HAS_THREADS
>     std::unique_lock<std::mutex> l(m);
>     if (!s) {
>       s = true;
>       c.notify_one();
>     }
> #endif
>   }
- `gecode/support/thread/thread.hpp` — > Event::wait(void) {
> #ifdef GECODE_HAS_THREADS
>     std::unique_lock<std::mutex> l(m);
>     c.wait(l, [this]{return this->s;});

> #endif
>   }

## Limitations

- The captured sources do not specify the public control-handle ownership or destruction protocol. This design assumes the engine-owned scheduler and its per-worker events outlive every worker; the separate API research must define how an external handle stops publishing updates before destruction.
- `Support::Event::signal()` acquires an internal standard mutex. The proposed update is nonblocking with respect to search, worker, and lifecycle locks, but the captured implementation cannot prove strict wait-freedom. The API contract should use that narrower meaning or introduce a different notification mechanism.
- The progress argument assumes each existing propagation, recomputation, callback, and steal scan terminates and that runnable threads receive OS scheduling. The captured sources provide no stronger scheduler-fairness guarantee.
- The sources contain no measurements for the atomic boundary check, O(maximum) growth/lifecycle notification, resize convergence, or resident parked-thread cost.
- RBS and PBS implementation sources are not in this packet, so this result does not verify their handle transport or stop propagation.

## Recommendations

- Record this state machine as the implementation boundary: independent logical state and slot lease, `n_busy` unchanged by parking, owner-prioritized round-robin handoff, and lifecycle commands that bypass slot admission.
- Implement the scheduler in the shared parallel engine and make DFS and BAB call the same boundary routine. Change `find()` to report success so a failed complete steal scan can trigger direct slot migration.
- Add assertions under the scheduler mutex: `n_slots <= maximum`, unique lease ownership, `requested >= 1`, no parked worker marked with a slot, and under stable C_WORK, `n_busy > 0` implies a lease or pending handoff.
- Instrument tests with boundary hooks to force limit changes before and after event signaling, before event wait, during C_WAIT, inside both reset acknowledgements, after failed stealing, during BAB incumbent delivery, and immediately before termination.
- Validate progress with a search tree where the only remaining branch is current state in a parked worker and has no stealable alternative; the active worker must fail its scan and hand over the slot.
- Benchmark the unchanged maximum path separately from dynamic mode. Measure one atomic requested-limit load plus the local lease branch, and measure O(maximum) wakeup cost only for limit growth and lifecycle transitions.
